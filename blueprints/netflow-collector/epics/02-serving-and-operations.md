## Data model touched here

| Entity | Fields this epic adds or reads | Notes |
|---|---|---|
| `flow_records` | reads `received_at`, `seq`, `exporter_id`, `src_addr`, `dst_addr`, `protocol` and every projected field | Read-only. The API never writes. The keyset predicate is `(received_at, seq) < (?, ?)` with `ORDER BY received_at DESC, seq DESC`, served by `idx_flow_records_received_seq`; the `exporter_id` and `src_addr` filters are served by their own composite indexes |
| `exporters` | reads `id`, `ip_address`, `label`, `first_seen_at`, `last_seen_at` | `GET /v1/exporters` returns all rows unpaginated — the fleet is hundreds of devices, not millions |

This epic adds **no** tables and **no** migrations. API keys are a configuration value, not a row
(see Conventions), and there is no `idempotency_key` table because every `/v1` endpoint is a read.

## Conventions that bite in this area

- **One envelope, every endpoint, including errors.** Success:
  `{"data": ..., "meta": {"next_cursor": ..., "has_more": ...}}`. Error:
  `{"error": {"code", "message", "details", "request_id"}}`. A 200 carrying an error inside is never
  acceptable.
- **Error codes and status:** `validation_error` 422, `bad_request` 400, `unauthorized` 401,
  `not_found` 404, `method_not_allowed` 405, `backend_unavailable` 503, `internal_error` 500.
- **The request struct is the only description of the parameters.** The OpenAPI builder reflects over
  the same struct and its `validate` tags, so `docs/openapi.json` cannot drift from the handler.
  Never hand-edit the document; regenerate it in the same commit as the change.
- **`start` and `end` are required** on `/v1/flows`; the range is half-open `[start, end)`. There is
  no unbounded scan of `flow_records` from the API, ever.
- **`limit` defaults to 100 and is clamped to 1000** — a client asking for more gets 1000, not a 422.
  An **unknown** query parameter, by contrast, is a 422 naming it: silently ignoring a typo'd filter
  returns a wrong answer that looks right.
- **Cursors are opaque and keyset-based**, base64url over `{"t": <received_at unix nanos>, "s":
  <seq>}`. Never offset pagination; never let the client construct a cursor.
- **Auth is middleware on the `/v1/` subtree only.** `/healthz`, `/readyz` and `/metrics` are
  registered outside it and stay public — the thing scraping them has no credential story, and what
  they expose is counters, not flow data.
- **Keys are a config value, not a table.** `NFC_API_KEYS` is a comma-separated list compared with
  `crypto/subtle.ConstantTimeCompare`; rotation is "add the new key, restart, move clients, remove
  the old, restart". A 401 logs at `warn` with the **first six characters only**.
- **`E2-T1`'s curl-style checks already send the API key header** even though `E2-T1` does not check
  it. That is deliberate: it is what keeps `E2-T1`'s gate green after `E2-T2` installs the
  middleware. Never write a gate that a later task will invalidate.
- **`-version`, `-dump-openapi` and `-healthcheck` short-circuit before config validation.** That is
  what lets later tasks tighten what a full boot requires without breaking earlier gates.
- **`/healthz` and `/readyz` are different endpoints with different meanings.** Conflating them turns
  a database blip into a restart loop.
- **The load test runs without `-race`.** The race detector costs roughly an order of magnitude and
  would fail the throughput floor. It is behind the `load` build tag for the same reason.
- **`.dockerignore` is written in the same task as the first image build** and must exclude
  `blueprints/`, `bin/` and `.git/` — the bundle lives inside the project and would otherwise be
  copied into the build context.
- **Distroless has no shell.** The container healthcheck is the binary checking itself
  (`-healthcheck`), not `curl` or `wget`.
- Every `Verify` command exits 0 when the task is correct. Where the right answer is a failure, the
  line asserts the specific code or the specific status (`test "$(curl ... -w '%{http_code}')" =
  401`), never a bare command and never `!` alone.

Full project rules: `CLAUDE.md`. Area rules: `.claude/rules/api.md`, `.claude/rules/testing.md`,
`.claude/rules/flow-contracts.md`. Both sit in the project root — the builder copied them there from
the bundle's `workspace/` before task one.

### `E2-T1` — Add REST query API with cursor pagination

**Depends on:** `E1-T7` · **Priority:** p0 — metadata for scope cuts, not a running order

`server.go` builds a `net/http.ServeMux` with method-and-path patterns (`GET /v1/flows`), a
middleware chain that assigns a `req_<hex>` request id, sets `X-Request-Id`, logs one line per
request with duration, and recovers panics into a 500 envelope. It also holds the OpenAPI builder:
reflect over the request structs in `flows.go` and their `validate` tags to emit the document, so
there is exactly one description of the parameters. `flows.go` binds the query string to a struct,
runs validator/v10, maps it to `flow.FlowQuery`, calls the `Querier`, and renders the envelope. Tests
use `httptest` with a fake `Querier` — no database, so this task stays fast. Commit the generated
`docs/openapi.json`; the gate diffs a fresh dump against it.

**Files**
- `internal/api/server.go` — new
- `internal/api/flows.go` — new
- `internal/api/api_test.go` — new
- `internal/app/run.go` — edit: start the HTTP server on `NFC_HTTP_ADDR`
- `docs/openapi.json` — new, generated by `./bin/collector -dump-openapi`

**Acceptance**

Copied verbatim from this task's `acceptance` array in `tasks.json`. Each one is decidable by a
command below, on this machine, during the build.

1. **WHEN** `GET /v1/flows` is requested with a valid `start` and `end` **THE SYSTEM SHALL** return 200 and a body shaped `{"data":[...],"meta":{"next_cursor":...,"has_more":...}}`.
2. **WHEN** `start` is missing, or `end` is not strictly after `start` **THE SYSTEM SHALL** return 422 with `error.code` `validation_error` and a `details` entry naming the offending field.
3. **WHEN** `limit` exceeds 1000 **THE SYSTEM SHALL** clamp it to 1000 rather than returning an error, and **SHALL** never return more than 1000 records in one page.
4. **WHEN** a `cursor` from a previous response is replayed **THE SYSTEM SHALL** return the next page with no record repeated from the previous page, and **SHALL** return 400 with `error.code` `bad_request` for an undecodable cursor.
5. **WHEN** any request is served **THE SYSTEM SHALL** set an `X-Request-Id` response header and use the same value as `error.request_id` on error responses.
6. **WHEN** `./bin/collector -dump-openapi` runs **THE SYSTEM SHALL** emit a document byte-identical to the committed `docs/openapi.json`.

**Verify** — every command, in order, run from the project root. Each one exits 0 when this task is
correct; the last one exiting 0 is what makes the task done.

```bash
go test -race ./internal/api/...
go build -o bin/collector ./cmd/collector
./bin/collector -dump-openapi > /tmp/nfc-openapi.json
diff -u docs/openapi.json /tmp/nfc-openapi.json
go vet ./...
go tool golangci-lint run ./...
```

The `diff` compares a freshly generated document against the committed copy of the **same
generator's** output — it is a drift check, not a hand-written literal, so it cannot encode a
prediction about a runtime this blueprint has not run.

**Checkpoint**

```bash

git tag step-08-query-api
git ls-files --error-unmatch docs/openapi.json   # expect: exit 0 — the generated doc is committed
```

### `E2-T2` — Add static API key middleware on /v1

**Depends on:** `E2-T1` · **Priority:** p0

A `func(http.Handler) http.Handler` that reads `Authorization: Bearer <key>` and compares the token
against every key in `NFC_API_KEYS` with `crypto/subtle.ConstantTimeCompare` — compare against all
of them rather than returning early, so response time does not leak how many leading bytes matched.
Install it in `server.go` around the `/v1/` subtree only. Missing header, malformed header and
unknown key all produce the same 401 `unauthorized` envelope with no hint about which. Deliberately
**not** built: an `api_key` table with hashing, prefixes, scopes, `last_used_at` and revocation. That
is `api-design.md`'s enterprise pattern and it is out of scope for a single internal operations
team; the upgrade path is to keep this middleware's signature and swap the key set for a cached
lookup.

**Files**
- `internal/api/auth.go` — new
- `internal/api/auth_test.go` — new
- `internal/api/server.go` — edit: wrap the `/v1/` subtree

**Acceptance**

1. **WHEN** a request to `/v1/flows` carries no `Authorization` header **THE SYSTEM SHALL** return 401 with `error.code` `unauthorized` and no flow data.
2. **WHEN** a request carries `Authorization: Bearer <key>` whose key is not listed in `NFC_API_KEYS` **THE SYSTEM SHALL** return 401 and **SHALL** compare keys with `crypto/subtle.ConstantTimeCompare`.
3. **WHEN** a request carries a key listed in `NFC_API_KEYS` **THE SYSTEM SHALL** return 200.
4. **WHEN** `/healthz`, `/readyz` or `/metrics` is requested without a key **THE SYSTEM SHALL** return its normal response and never 401.
5. **WHEN** a 401 is returned **THE SYSTEM SHALL** log at `warn` with only the first 6 characters of the presented key and never the whole key.
6. **WHEN** `NFC_API_KEYS` is empty while the API is enabled **THE SYSTEM SHALL** exit with code 2 at startup naming `NFC_API_KEYS`.

**Verify**

```bash

grep -q 'crypto/subtle' internal/api/auth.go
go build -o bin/collector ./cmd/collector
env NFC_API_KEYS= ./bin/collector -validate-config >/tmp/nfc-step9.err 2>&1; test $? -eq 2
grep -q 'NFC_API_KEYS' /tmp/nfc-step9.err
```

**Checkpoint**

```bash

git tag step-09-api-auth
```

### `E2-T3` — Add logging, metrics, tracing and health endpoints

**Depends on:** `E2-T2` · **Priority:** p0

`logging.go` configures `slog.NewJSONHandler` at `NFC_LOG_LEVEL` with a `ReplaceAttr` that redacts
any attribute whose key is on the redaction list (`authorization`, `api_key`, `dsn`, `password`,
`token`) — redaction lives in the logger, never at the call site. `otel.go` builds an OpenTelemetry
meter provider whose reader is the Prometheus exporter, registered into `client_golang`'s registry,
and a tracer only when `NFC_OTEL_ENABLED` is true; when it is false nothing must attempt an OTLP
connection. `ops.go` serves `/metrics` from `promhttp`, `/healthz` as an unconditional 200 while the
process can answer, and `/readyz` which pings every configured backend with a 2 s budget and returns
503 with `backend_unavailable` if any fails. Add the visibility-lag observation at batch-write
completion in the pipeline's write path via the existing instrument.

**Files**
- `internal/obs/otel.go` — new
- `internal/obs/logging.go` — new
- `internal/api/ops.go` — new
- `internal/obs/obs_test.go` — new
- `internal/app/run.go` — edit: initialise logging and the meter provider before anything else

**Acceptance**

1. **WHEN** `GET /metrics` is requested **THE SYSTEM SHALL** return 200 in Prometheus text format containing `netflow_records_ingested_total`, `netflow_records_dropped_total`, `netflow_batch_write_duration_seconds`, `netflow_batch_write_errors_total`, `netflow_pipeline_buffer_length` and `netflow_record_visibility_lag_seconds`.
2. **WHEN** `GET /healthz` is requested while the process is running **THE SYSTEM SHALL** return 200 regardless of backend state.
3. **WHEN** every configured backend fails its ping **THE SYSTEM SHALL** return 503 from `GET /readyz` while `GET /healthz` still returns 200.
4. **WHEN** a log line is emitted **THE SYSTEM SHALL** write single-line JSON carrying `time`, `level`, `msg` and `service`, and **SHALL** replace any attribute whose key is on the redaction list with `[redacted]`.
5. **WHEN** a batch write completes **THE SYSTEM SHALL** observe `netflow_record_visibility_lag_seconds` as the difference between write completion and each record's `received_at`.
6. **WHEN** `NFC_OTEL_ENABLED` is false **THE SYSTEM SHALL** still serve `/metrics` and **SHALL NOT** attempt to reach an OTLP endpoint.

### `E2-T4` — Add container image and CI pipeline

**Depends on:** `E2-T3` · **Priority:** p1

A multi-stage Dockerfile: `golang:1.27.1` builder doing `CGO_ENABLED=0 go build -trimpath

`NFC_HTTP_ADDR` + `/healthz`, exit 0 on 200 and 1 otherwise — distroless has no shell, so the binary
is the only healthcheck available. CI runs build, vet, lint, `go test -race -cover ./...` and
govulncheck on every push and pull request.

### `E2-T6` — Add load verification and whole-tree race gate

**Depends on:** `E2-T5` · **Priority:** p1

`load_test.go` behind `//go:build load`. Two scenarios. **Throughput:** offer 200,000 synthetic
records to the pipeline with an in-memory sink, measure wall-clock, assert at least 20,000
records/second and 0 drops — an in-memory Go pipeline does far more than that on any modern machine,
so the floor tests that nothing pathological was introduced rather than the hardware. **Conservation
under overload:** a sink that sleeps per batch, offered records far faster than it drains; assert
`ingested + dropped == offered` exactly and that the pending buffer never exceeded
`NFC_PIPELINE_BUFFER`. Conservation is the hardware-independent invariant and the real requirement —
a record must never vanish uncounted. Record the measured numbers in `docs/performance.md` under the
three gated headings, and add a nightly CI job that runs the load tag.

**Files**
- `internal/pipeline/load_test.go` — new

## Pitfalls

- **Hand-editing `docs/openapi.json`.** The gate regenerates and diffs it; a manual edit fails on the
  next run and teaches everyone to distrust the gate. Change the request struct instead.
- **Returning 200 with an error inside.** It defeats every client, retry policy, cache and monitor in
  the chain, and `/readyz` in particular must return a real 503 or the orchestrator never notices.
- **Putting auth on `/metrics`.** Prometheus has no credential story here; the middleware goes on the
  `/v1/` subtree only.
- **Returning early from the key comparison loop.** Comparing against keys until one matches leaks
  timing. Compare against all of them and OR the results.
- **Forgetting `CGO_ENABLED=0`.** The binary builds, then fails at container start with a missing
  libc — distroless has none. The Go track calls this the whole point of the track.
- **Writing `.dockerignore` after the first build.** The bundle at `blueprints/` goes into the build
  context, the image is enormous, and the cause is invisible from the Dockerfile.
- **Running the load test with `-race`.** It fails the throughput floor on perfectly correct code and
  reads as a performance regression.
- **`go mod tidy` without `-diff` inside a gate.** It mutates `go.mod` as a side effect of checking
  it. `-diff` reports and exits 0 when clean.
- **Asserting a count that the blueprint did not compute.** `grep -qx '13'` on the tag count is
  legitimate because 13 is the number of steps this bundle defines and `tasks.json` has 13 entries.
  Do not invent a similar count for tests or routes.
